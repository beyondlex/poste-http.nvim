## 本轮修复（每个修复都先验证测试在未修复时失败）

1. **`execute_all_requests` 的 prompt 取消使批次崩溃停摆**（import.lua）
   ——`run ./batch.http` 逐块执行时，用户取消某个 `<<var` 的取值输入，
   `resolve_import_content` 回调拿到 nil，直接喂给 `find_block_end`
   （`vim.split(nil)`）抛错，`execute_next()` 不再执行：剩余请求静默
   丢弃，批次回调也永不触发。取消的请求现在记为 status 0 /
   `Cancelled` 并继续批次。单请求路径（execute_run_directive）原本就
   有 nil 判断，两路径行为对齐。
2. **gsub 替换串把响应值当模式展开**（request_deps.lua）——
   `{{Name.response.body.*}}` 替换用了字符串形式的 replacement，
   响应值里的 `%`（URL 编码、base64、纯 "100%"）会被读成捕获引用：
   报 "invalid use of '%'" 或静默改写 body / 文件级 @var 行。改为
   函数替换，值按字面落盘；body 与 @var 两条路径各有回归 spec。
3. **`json_pretty` 不转义 object key**（format_file.lua）——格式化含
   `"` / `\` 的 key 的 JSON body 时重新输出非法 JSON（字符串分支有
   转义、key 分支没有）。抽出的 `json_escape_string` 两者共用；该模块
   同时补上了缺失的第一个 spec。
4. **`prompt_vars` 取消后继续弹后续 prompt**——cancelled 标志只在
   遍历结束时检查，用户取消一个 `<<var` 后仍要逐个关掉剩下的
   select/input，而结果注定被丢弃。`process_next` 现在取消即短路
   `on_complete(nil)`；新增首个专属 prompt_vars spec（含短路断言）。
5. **variable_inspector 重复注册 `q`/`<Esc>`**（两处完全相同的
   keymap 块，二次绑定覆盖一次）——保留一份；无行为变化。
6. **nav/util `show_references` 的死 previewer**——一个 20 行的
   setmetatable 预览器从未接入 select 调用（F15 重构遗留），连同
   仅被它使用的 `filetype`/`total` 局部一起删除。
7. **杂项**：仓库根目录误跟踪的 0 字节 `nvim.log` 移出 git 并加入
   .gitignore。
8. **Lua 导入模块缓存加 mtime 失效**（import.lua，09-09 报告遗留项）
   ——编辑被导入的 Lua 数据文件后整个 session 都不生效；缓存条目现在
   按 mtime key（graphql_schema/grpc_proto 先例），两处重复的加载代码
   合并为 `cached_lua_exports` 助手（日志行为不变），附失效回归 spec。
