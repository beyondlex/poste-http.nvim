## 本轮修复（每个修复都先验证测试在未修复时失败）

1. **历史详情的 jq 过滤失败会清空面板**（history.lua）——
   `history_jq_filter` 把 pcall 成功当 jq 成功，但 `vim.fn.system` 只捕获
   stdout：非法查询以非零码退出、输出为空，面板被空结果覆盖且无任何
   提示——`json.apply_filter` 早有 `shell_error == 0` 守卫，这里漏了同款。
   过滤体抽成 `M.apply_jq_filter(entry, query, buf)`（keymap 负责解析当前
   条目），`M._run_jq` 暴露给 spec（headless 无法强设 `vim.v.shell_error`）。
   失败路径：notify ERROR + 面板与条目原样保留；顺带删除了死占位
   `local _ = nil`。
2. **`ai/blocks.truncate` 在字节切点撕裂 UTF-8**——AI 上下文按字节预算
   截断（4096/8000），CJK 块名/响应体切在多字节序列中间时给 prompt 发
   非法字节。切点现在回退到最后一个 lead byte、序列不完整则整体丢弃；
   完整序列与 ASCII 尾部不动。spec 对 36 字节 CJK 串的每个切点做
   iconv 有效性断言。
3. **`ai/auto_context` 的 8000 字节截断同病**——裸 `:sub` 改为复用
   `blocks.truncate`（两处一个语义，一个实现）。

## 记录在案（不确定 / 有意保留）

- **断言运行时错误不计入 `failed`**（http/assertions.lua）：`client.test`
  全过后顶层 error → `passed=N, failed=0` 但 `results.error` 置位——
  run.lua 据此 add_error → errors tab + 指示灯都会亮，语义是 09-08 有
  意钉死的（"summary 不得宣称通过的测试失败"）。唯一残留：assertions
  tab 的汇总图标可能显示 ✓（错误行就在下面）。与语法错误路径
  （total=1/failed=1）不一致，改哪边都是产品决策，保持现状。
- **history 持久化的 body 截断**（`MAX_BODY_SAVE` 处 `:sub`）理论上可
  切坏 UTF-8；载荷是原样字节塞进 JSON 字符串，load 端 decode 失败即整
  条跳过——自愈，未观察到实际损坏。
- **日志行 `:sub(1, 500)`**（curl/grpcurl/websocat argv 日志）可切在
  UTF-8 中间；仅落日志文件，渲染层 nvim 容忍，不值得为日志改字符切。
- **`format/util.lua` 的 `json_escape` 与 `format_file.lua` 的
  `json_escape_string` 重复**：同仓库两份转义实现、各有 spec。合并方向
  是 format_file 复用 format/util（或反之），留作下次触碰时的 DRY 项。
- **`url_decode` 的 `gsub("+", " ")`**：裸 `+` 在 PUC Lua 是 malformed
  pattern，但 nvim 的 LuaJIT 按字面处理——当前平台无恙，若换解释器需
  改 `"%+"`。
