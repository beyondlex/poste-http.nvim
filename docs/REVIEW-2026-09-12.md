## 本轮修复（每个修复都先验证测试在未修复时失败）

1. **`.res.` 简写引用永不替换**（request_deps.lua）——
   `find_request_variable_refs` 把 `.res.` 归一化成 `.response.` 做识别与
   取值，但 `substitute_and_finish` 用归一化后的 `{{Name.response.body.x}}`
   去 gsub **未归一化**的原文——模式永不命中：依赖照常执行，字面
   `{{Login.res.body.token}}` 却留在请求里发出去。文档
   （docs/user/syntax.md、variables.md）一直把 `.res.` 当一等语法。
   现在 ref 携带两份拼写：`full` 保留用户原文（替换用），`norm` 归一化
   （缓存取值用）；`find_dynamic_prompt_refs` 同步修掉——此前提示变量
   里的 `.res.` 引用干脆识别不到（它只匹配长拼写的 `.response.`）。
   回归测试两个：块内替换 + 文件级 `@var` 行替换。
2. **OpenAPI/Swagger 导入器宣称支持 YAML 却只解析 JSON**
   （import_openapi/import_swagger/import_parser）——文件选择器给了
   `yaml/yml` 扩展名，`read_spec` 只跑 `vim.json.decode`：选 YAML 必然
   以一句干巴巴的 "Invalid JSON" 失败。选择器收窄为 `json`；
   `read_spec` 对形似 YAML 的内容给出明确提示
   （"looks like YAML — only JSON specs are supported"）。新增
   import_yaml_spec 钉住选择器扩展名与 YAML 诊断两条路径。
3. **ts_query 的 `parent_of_type` 泄漏全局变量**（ts_query.lua）——
   `ok, parent = pcall(node.parent, node)` 复用了上一行的 `ok` 但没声明
   `parent`，每层循环写一次 `_G.parent`。`.luacheckrc` 的
   `allow_defined = true` 恰好把这类全局写入从警告里抹掉了，功能上碰巧
   无害。改为局部；学习已记入 LEARNINGS.md。

## 记录在案（不确定 / 有意保留）

- **verbose.lua 的模块级 `_sep_lines`/`_section_lines`**：`format_verbose`
  在无 response（pending 渲染）时把布局索引落在模块级，由同一次
  `apply_verbose_highlights` 消费后清空。两次渲染交错时理论上会串页；
  现实中 render 是同步串行的，保持现状。
- **`format_elapsed(ms, pending_start_hires)` 第二参数是死代码**——唯一
  调用点只传一个参数，pending 的耗时在 format_verbose 里独立计算。
  下次触碰该文件时顺手删。
- **verbose.lua:264 `val:gsub("+", " ")`**：裸 `+` 在 PUC Lua 是 malformed
  pattern，LuaJIT 按字面处理——与 09-11 记录的 `url_decode` 同款、同
  结论（当前平台无恙）。
- **nav/text.lua 的 alias 光标估算**：`alias_start = as_pos + 4` 假定
  `as` 前恰好一个空格，多空格时 gd 的命中区间偏移。只影响精确落在
  alias 上的光标判断，启发式路径，不值得加状态机。
- **import_openapi/import_swagger 的 `pairs(spec.paths)`**：块顺序随哈希
  序变化，每次导入同一 spec 可能生成不同顺序的 .http。导入是一次性
  动作，排序属锦上添花。
- **`util.redacted_cmd` 只脱敏 `-H/--header`**：cookie jar 走 `-b <file>`
  （文件路径非凭据），curl `-u` 在 argv 构建路径中未使用——当前无泄漏
  面；若未来加 `-u` 支持需同步扩展 SENSITIVE 处理。
- **context_detector 的 TS/regex 双实现**：同一套上下文判定维护两份
  （`ts_detect_context` 与 `detect_context`），comment-operator、run
  target、status_code 三块逻辑镜像重复。这是 TS 可选 + 回退的既定
  架构，靠 tests/contract 的 fixture 对齐，暂不合并。
