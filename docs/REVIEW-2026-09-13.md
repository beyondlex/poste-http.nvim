## 本轮确认（未发现新 bug 的关键证据）

- **jobstart 跨 callback 行分割**：poste-http 两条流式路径都已正确处理——
  curl_exec 用 `stdout_buffered = true`（nvim 缓冲到退出一次性交付），
  ws_session 用 `util.line_splitter()` 持有残段。本轮用真实进程探针
  （单行 70KB 分两次写入）验证了 nvim 的 data 数组跨界约定，并确认
  **poste-mq 的三处拼装是坏的**（callback 间误用 "\n" 连接）——已在
  poste-mq 仓修复，家族经验以此传导。
- **gsub 替换串陷阱**：request_deps 的 `{{...}}` 替换全部走
  `function() return value end`（响应值含 `%` 时字符串替换会被当成捕获
  引用），模式侧 `vim.pesc` 齐备。
- **busy 泄漏面**：handle_curl_response / handle_directive_response /
  orchestration 的全部早退路径都在 pcall 之后统一 `state._busy = false`；
  prepare_request 的取消路径、pre-script 错误路径、unresolved-vars 快败
  路径各自清 busy。
