## Fixed this round

1. **`{{$uuid}}` repeated across sessions (same root cause as poste-mq)** —
   nothing in the repo ever called `math.randomseed`, and LuaJIT starts its
   PRNG with a fixed state: the first `{{$uuid}}`/`{{$randomInt}}`/
   `{{$timestamp}}` suffix of every nvim session was identical, colliding
   idempotency keys run over run. `util.seed_random()` now seeds once on
   first use (wall clock + monotonic ms + pid); wired into
   `http/vars.lua` `_resolve_magic` and `form_data.lua`'s magic-var
   generation. Regression specs: two real subprocesses must not share the
   sequence; `substitute()` must arm the seeding; one-shot seeding enforced.

2. **history `_detail_cursor` bookkeeping** (REVIEW-2026-09-13 follow-up) —
   `hide()` drops the map (cursor memory only matters while the browser is
   open), `delete_entry` and the `add_entry` ring-trim prune their entries.
   The declaration moved above its first use — a local read before its
   declaration line resolves to a nil global (family pitfall; same shape as
   dialect.safe_number over in poste-mq).

## Recorded, not fixed (uncertain / deliberate)

- **`run.lua handle_curl_response`: the `vim.tbl_extend("keep", {...},
  state.pending_request)` is a provable no-op.** The right-hand table wins
  on key conflicts and `pending_request` always already carries
  method/url/timestamp (set in `start_curl_exec`), so the overlay never
  changes anything. The intent was presumably to refresh those fields from
  the response; the fields below it (request_headers/request_body/…) do the
  real work. Left untouched — behavior-neutral; safe to delete next time
  the file is touched.
- **`global_headers.merge` replaces duplicate per-request headers** when a
  global header with the same name exists: the merge is keyed by lowercased
  name, so a second same-name per-request header overwrites the first at
  its slot instead of being appended. Without global headers duplicates
  pass through untouched — inconsistent only in the globals-present case.
  Duplicate request headers are rare; left as-is.
- **`scripts.inject_pre_script_vars` / `inject_global_vars` cannot carry
  multi-line values** — script-set values are injected as `@var = value`
  lines, so a value containing a real newline corrupts the request text
  (the tail becomes a stray line the parser must reject). Fixing needs an
  encoding the var collectors round-trip; no known real-world hit.
- **`assertions.lua`: `response.headers[nil]` errors** — the `__index`
  handler calls `k:lower()` unconditionally, and `rawget(t, nil)` raises.
  Only reachable from a script bug, and the sandbox pcall surfaces it as a
  failed test, so behavior is acceptable.
- **`websocket.lua` `r[ea]direct`-style verbose-log fallbacks** live in
  response_parser (redirect count / final URL) and depend on curl's log
  wording; the primary source is `--write-out %{num_redirects}` in a temp
  file, so the fallback is belt-and-braces only.
