## Fixed this round

1. **curl import: `\"` escapes corrupted quoted bodies** — the tokenizer
   closed a double-quoted string at the first raw `"` even when preceded by
   a backslash, so Windows-style pastes like `-d "{\"name\":\"test\"}"`
   imported as the mangled body `{\name\:\test\}`. Double quotes now honor
   `\"` / `\\` escapes (POSIX rules); single quotes stay literal.
2. **curl import: the URL was the LAST bare argument** — any unmapped flag
   with a separate value replaced the real request target:
   `curl https://api.example.com -o out.txt -u alice:s3cret` imported
   `url = alice:s3cret` (reproduced before the fix). The URL is now the
   FIRST bare arg (curl semantics), known value flags (-o/-u/-m/-A/-e/-b/
   -x/-m/--connect-timeout/--retry/…) consume their value in separated,
   attached (`-m10`) and `--flag=value` shapes, and `--url`/`--url=` are
   handled.
3. **winbar `%` injection** (same bug poste-mq fixed in its winbars on
   09-17, landed here a day later) — a literal `%` in user-controlled text
   is a statusline flag: a jq query `.p | 100%` in the Body tab label or a
   request name `### 50% off` in the `[1/3] Name` label mangled the
   response/history winbar and `%*` cut the highlight run short.
   `ui/winbar.escape()` lands in the module the guardrails designate as
   the only winbar string builder; `render_tabs`/`http_env` escape their
   data inputs at that choke point, `buffer.update_winbar` escapes the
   response name.
4. **unresolved-var gate skipped header NAMES** (resolves a 2026-09-17
   "recorded, not fixed" item) — the fail-fast check collected URL, body,
   and header VALUES only; a literal `{{var}}` in a header NAME went to
   curl verbatim. Part collection moved to `run.unresolved_var_parts`
   (M-level, spec-asserted) which includes the name half.

## Feature: curl import now understands -F and -u

- `-F`/`--form` parts import as a multipart body in the .http shape
  (boundary + Content-Disposition lines); `name=@file` parts keep a LIVE
  `< path` ref instead of baking content in, so re-runs pick up file
  changes and binary uploads never pass through the text importer. An
  explicit multipart Content-Type's boundary is reused; otherwise one is
  generated. `;type=`/`;filename=` directives on file parts are stripped;
  `--form-string` keeps `@`/`<` literal; mixing `-d` with `-F` is a curl
  usage error and `-d` wins. Before this change `-F name=value` pieces
  leaked into the URL scan as bare arguments.
- `-u`/`--user` imports as `Authorization: Basic <base64>` (vim.base64,
  nvim 0.10+), so the pasted request actually authenticates.

Round-trips with `copy_as_curl`'s `build_multipart_flags` parser (the .http
multipart shape is now read and written by both directions).

  unchanged this round; still low risk (paste output, not executed by us).
- **`cache.extract_request_block` describe-fails fallback skip set** —
  still diverges from `find_request_line` on pre-script lines (09-17
  item); untouched this round, align next time cache.lua is edited.
- **`json.get_key_paths` enumerates every array index** (`.items[0]`,
  `.items[1]`, …) — a 1000-element response floods the jq picker with
  index paths. Display-only; a cap would need a UX decision (keep N?
  collapse to `[]` only?).
- **folding separator caches are keyed by bufnr but never evicted** —
  bounded by distinct buffers opened per session (a few bytes each);
  harmless, noting for completeness.
- **`env.sync_winbar` also claims `.rest` files** — `%.rest$` is matched
  even though ftdetect may not map `.rest` to poste_http; winbar-only
  effect, no runtime path depends on it.
