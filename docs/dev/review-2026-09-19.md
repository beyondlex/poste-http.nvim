## Fixed this round

1. **curl import: multiple `-d` pieces overwrote each other** — the
   importer kept only the LAST `-d`; curl concatenates every
   `--data-*` piece with `&` in command order (`-d a=1 -d b=2` sends
   `a=1&b=2`, verified against curl 8.7.1). All data pieces now feed one
   ordered list; `--data-urlencode` pieces are encoded at add time and
   keep their position in the sequence.
2. **curl import: quoted boundary produced an unparseable body** — an
   explicit `Content-Type: multipart/form-data; boundary="My B"` kept its
   quotes through extraction, so delimiter lines became `--"My B"` while
   a server reads the parameter value as `My B` (RFC 2045). Quotes are
   now stripped before the delimiter is used. (Also noted while probing:
   modern curl never reuses the user's boundary for `-F` parts at all —
   it appends its own as a second `boundary=` param. The importer's
   "reuse the explicit boundary" behavior is self-consistent, which is
   what a .http file needs, so it stays; recorded here for the record.)
3. **curl import: `-G`/`--get` was silently ignored** — data flags
   promoted the method to POST with a body; now the joined data rides on
   the query string (`&` when the URL already has a query), the method
   stays GET unless `-X` forces a token (curl sends `PUT /?a=1` for
   `--get -X PUT -d a=1` — verified), and the body is dropped.
4. **response_parser: relative Location replaced response.url** —
   `Location: /new` in the verbose log cannot be resolved without
   replaying each hop's base URL; it used to replace the request URL
   verbatim, leaking a bare path into history and `{{response.url}}`.
   Only absolute http(s) Locations become the effective URL now.
5. **parse_error content_type fallback never fired** — the code said
   `parsed.content_type or "text/plain"` but `parse_headers_file`
   returns `""` (not nil) when no headers arrived. Error responses now
   report `text/plain`.
6. **json: the no-jq jsonpath fallback rejected its own candidates** —
   `get_key_paths()` offers `.items[].name`, but the evaluator looked the
   key up on the array itself and answered "Key 'name' not found". A key
   applied to an array now maps across its elements (jq semantics).

## Feature: jq picker index-path cap (resolves the 09-17 ledger item)

`get_key_paths()` enumerated every array index, so a 1000-element
response flooded the jq filter picker. Decision made this round: each
array contributes the `[]` wildcard (always replayable, also by the
no-jq evaluator) plus at most the first 3 numeric indices
(`MAX_INDEX_PATHS` in json.lua). That keeps "pick a concrete element of
a short array" one keypress away while bounding long responses; docs
synced to the site's response-views page.

## Recorded, not fixed (uncertain / deliberate)

- **Lua imports execute unsandboxed** — `import helper.lua` runs the file
  with plain `load()` (full stdlib, io/os included), while `### Script`
  blocks and assertions run in the script_sandbox whitelist. The
  sandbox's own rationale (".http files are shared, their scripts run on
  execution") applies to imported Lua just as much; but sandboxing
  imports would break legitimate modules that `require` libraries or do
  file I/O by design. A middle ground (sandboxed-by-default, opt-out
  flag) needs a product decision, so it stays recorded here.
- **`util.shell_escape` strings starting with `-`** (carried from
  09-16/09-17): unchanged; still low risk (paste output, not executed by
  us).
- **`resolve_reference` treats any dotted name as `alias.Name`** — a bare
  import's request named `Get User.v2` resolves as alias "Get User",
  name "v2" and fails. Rename-the-request is the current workaround;
  disambiguation syntax would need a grammar decision.
- **Combined short flags with a trailing value flag** (`-sSo out.txt`)
  — the generic short-flag branch can't know `o` (last letter) takes a
  value, so `out.txt` leaks in as a bare arg. Long-form `-sS -o out.txt`
  works; rare in pasted commands.
- **curl `--data-urlencode` encodes space as `%20`, curl sends `+`** —
  semantically equal for form decoding; tests pin `%20`. Recording the
  byte-level divergence so nobody chases it later.
- **folding separator caches keyed by bufnr, never evicted** (carried
  09-18): unchanged.
