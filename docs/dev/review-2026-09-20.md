# Review Notes — 2026-09-20

Scope: full test baseline (107 spec files green at start) + fresh-eyes read of
modules NOT covered by the 09-16…09-19 passes: file_include, lua_docs,
_methods, env, var_collector, folding, outline, the request-chaining pipeline
(resolve / request_deps / request_vars / prompt_vars / jq_mapping /
nested_access / vars), errors, ws_session + the websocket executor wiring, and
a doc-drift sweep of the `< path` claims.

## Fixed this round

1. **file_include: an unreadable include target silently emptied the body** —
   `io.open(dir, "rb")` succeeds (fopen on a directory is legal), the read
   fails, and the nil used to be swallowed by `table.insert` — the include
   line vanished and a body that was only `< path` went out EMPTY, with no
   error. Unreadable targets now abort the run with `Cannot read file: …`
   like missing files already did. New `tests/http/file_include_spec.lua`
   pins expansion (absolute/relative/tilde), script-opener exclusion, the
   missing-file error, and this regression.
2. **prompt_vars: `.request.` dynamic prompt refs fell through to garbage
   static options** — `find_dynamic_prompt_refs` (request_deps) accepts both
   sources and executes the dependency for them, but the prompt-select path
   only matched `.response.` refs, so `<<var [{{X.request.body.y | …}}]` ran
   the dependency and then offered the raw ref text as a bogus option. Both
   sources take the dynamic path now; the new spec case drives `.request.`
   end-to-end (dep executes once, jq mapping feeds the picker, selection
   lands as `@var`).
3. **errors: jump targets lost when a sourceless error precedes them** —
   `apply_highlights` guessed detail lines with an `expect_source` flag armed
   by the previous message line. An entry whose source carries no detail
   (post_script's `{ file }` has no line) writes none, so the NEXT error's
   message was consumed as the missing detail, its own detail line then read
   as a message (mis-highlighted), and its jump target was lost.
   `format_errors` now indents detail lines at 4 spaces and the highlighter
   dispatches on that prefix, tracking the owning error per message line.
4. **ws_session: interactive session is live at spawn, not at first inbound
   frame** — a server that only receives never sends a frame, and keymap
   registration plus the first `on_progress` both waited for one: the
   response panel had no `s`/`c` keys and run.lua's busy flag stayed held
   (every other run answered "Request already in progress") with no visible
   way out. A scheduled initial progress now opens the Msgs tab, releases
   busy, and registers the panel keys right after run.lua's synchronous tail
   completes. Inbound-frame streaming is unchanged.

## Docs (repo + doc-poste site)

- `docs/user/syntax.md` / `docs/user/form-data.md`: the `< path` claims never
  matched the code. "Only valid inside multipart" and "removed for JSON body
  embedding" were false — `curl_exec` expands `< path` on the request body
  regardless of Content-Type (probed headless), and a missing file aborts the
  run (never "preserve the line with a warning"). Docs now describe the real
  behavior and keep the Lua-import recommendation for external JSON (imported
  values resolve as variables; `< path` inserts bytes).
- doc-poste site `poste-http/syntax.mdx`: same corrections synced in the same
  change set (warning box → note, rules list updated).

## Recorded, not fixed (uncertain / deliberate)

- **request_vars public wrappers have no production callers** —
  `resolve_request_variables`, `resolve_content_dependencies`, and
  `handle_prompt_variables` are only reached via tests; the runtime pipeline
  goes through `resolve.resolve` (which calls the `_impl` paths and
  deliberately does NOT reset the response cache, unlike the public
  `resolve_content_dependencies`). Candidate for a future cleanup; kept as
  API surface for now.
- **prompt_vars bounds vs substituted content** — block bounds come from the
  buffer cache but index the `content` lines; a substituted value containing
  a newline would shift the dep block's bounds. Single-line `json.encode`
  output makes this unreachable in practice today.
- **Request names containing `.response.`/`.request.`** — split_request_ref
  takes the FIRST marker, so such names are ambiguous. Inherent grammar
  limit; rename is the workaround (same spirit as the 09-19 `alias.Name`
  note).
- **`load_env_vars_with_lines` brace counting** — unbalanced braces inside a
  JSON string value end the env section early. Diagnostics-only path
  (var-line mapping), best-effort by design.
- **lua_docs `try_lsp_hover` column clamping** — non-block_end lines don't
  clamp the cursor column to the line length; LSP servers clamp on their
  side, benign.
- **outline non-TS path reads from `start_line` via 0-based
  `nvim_buf_get_lines`** — the `###` line is therefore excluded from the
  scan and the `^#` skip inside never fires. Correct by accident; recorded so
  nobody "fixes" it into a double-skip.
- **file_include reads CRLF text verbatim** — no `\r\n` normalization since
  the binary-safety fix (ea1ef14). A CRLF text file inserts `\r\n` bytes;
  deliberate, noted for the record.
- **folding separator caches keyed by bufnr, never evicted** (carried from
  09-18): unchanged.
