## Fixed this round

1. **format: textual mimes misrouted to the binary-file path** — both
   format_body and format_verbose decided binary vs text with a bare
   "mime mentions text/json/xml/html" substring check. A response with
   `Content-Type: application/x-www-form-urlencoded` (probed headless)
   was dumped to a `.bin` file and the Body view showed a
   "Binary File Response" card instead of the payload;
   `application/javascript`, `application/x-yaml` and friends suffered
   the same. format/util now owns a shared `is_text_content_type()`
   (+json/+xml suffixes, explicit textual list; unknown types still
   default to binary, empty type counts as text) plus the
   content-type→filetype map that format.lua and format/verbose.lua each
   kept a drifted private copy of. urlencoded bodies render as decoded
   key-value lines in the Body view too (matching the verbose view), and
   a large body with an empty Content-Type no longer flashes the binary
   card. Regression spec: `tests/http/format_binary_detection_spec.lua`.
2. **verbose: Query Parameters decoded %XX before '+'** — an encoded
   literal plus (`?q=a%2Bb`) collapsed into a space in the Query
   Parameters display, the exact wrong order the shared util decoder
   documents. The display now goes through `fmt_util.url_decode` (keys
   included). Same spec file.
3. **import_parser: enum-valued header params emitted no header** —
   `collect_parameters` only re-attached `{{name}}` for query params in
   the enum branch; a header parameter with enum values produced the
   `<<X-Region [us, eu]` prompt line but no `X-Region: {{X-Region}}`
   header, so the generated request was silently missing the parameter.
   Header enums emit the header now (path enums already work via the
   `{{param}}` URL rewrite). Spec in zero_coverage_smoke_spec.
4. **format/messages: table-shaped sent frames crashed the view** —
   received frames go through the `frame_data` normalizer, sent frames
   were concatenated raw. Both normalize now (ws_session stores plain
   strings today; the guard is for shape drift).
5. **script_snippet: expansion guarded on the current buffer** — expand()
   validated the stored buffer and cursor line but not the current
   buffer; a same-line-number coincidence in another buffer could edit
   the buffer the snippet was armed in.
6. **format: `detect_filetype` honors the +xml suffix** — +json was
   mapped but +xml fell through to text (RFC 6839 symmetry).

## Recorded, not fixed (uncertain / deliberate)

- **state.set_responses `idx or (#chain or 1)`** — the inner `or 1` is
  dead: `#chain` errors on nil rather than yielding nil, so a
  set_responses(nil, nil) call crashes instead of defaulting. All three
  call sites pass a table today; hardening is one line if ever touched.
- **format_verbose's `_cached_verbose` read is dead on the normal path**
  — only the protocol=="error" early return sets it; normal verbose
  views recompute per render. Caching would freeze `opts.width`
  (captured per render into `_fmt_width`), so the current behavior is
  the safe one; the asymmetry is easy to misread as a bug.
- **select.lua pick_snacks assumes `snacks.picker` exists when the
  snacks module loads** — the caller gates on `pcall(require,
  "snacks.picker")`, which in practice implies `snacks.picker`, but a
  hypothetical partial snacks install would error inside pick_snacks.
- **symbols.collect_requests: a RUN line followed (in the same block) by
  a line matching `^%s*(%u+)%s+(%S+)` would overwrite the RUN row** —
  request blocks after a RUN directive normally carry only scripts and
  comments, so unreachable in practice.
- **import_parser.make_filename on an all-symbol title yields
  `.http`** (empty stem) — cosmetic import edge.
- **import_postman bakes collection-variable VALUES into request lines**
  while also emitting the `@var = value` file header — editing the
  declaration afterwards does not affect the baked blocks. Self-contained
  output looks deliberate (unknown vars stay symbolic), but keeping the
  `{{name}}` refs live would match how import_openapi generates
  `{{base_url}}` + `@base_url`. Candidate behavior change, not a defect.
- **verbose.lua duplicates content_type_map** — resolved this round via
  format/util (shared table), noted here for the ledger trail.
- **multipart.strip_request_preamble splits/rejoins on `\n`** — a lone
  `\r\n` round-trips (each `\r` stays attached to its line), consistent
  with the binary-safety stance; recorded so nobody "fixes" it into a
  normalization pass.
