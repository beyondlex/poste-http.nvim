# Review Notes — 2026-09-24

Scope: full test baseline (112 spec files green at start) + an
adversarial-data pass. Every module was read through in the 09-16…09-23
rounds, so this round attacked the pure cores with inputs and paste
shapes instead: NUL bytes and binary-derived text, empty values,
multi-index paths, unterminated user constructs, tokenizer edge
arguments (ui/text, nested_access, vars, curl tokenizer, response
parser, redaction helpers, multipart, block_boundary, assertions,
script_sandbox, env, history).

## Fixed this round

1. **ui/text: one NUL byte killed every render path** — a literal
   `\u0000` (from a JSON variable value or a binary-derived response
   preview) turns the Lua string into a Blob the moment it crosses into
   `vim.fn.strdisplaywidth`: Vim E976, and the winbar/outline/history
   render that called `truncate()` died with it. `strip_nul()` now drops
   NULs at the door of both `truncate` and `middle` (they carry no
   displayable content). Spec: `tests/ui_text_spec.lua` (+4, real NUL
   bytes — raised before the fix).
2. **nested_access: consecutive indexes never traversed** — the resolver
   matched ONE bracket per segment, so `data[0][1]` looked the base up as
   the literal key `"data[0]"` → nil. `get_key_paths()` emits such paths
   for 2-D arrays and `{{Req.response.body.data[0][1]}}` refs resolve
   through here, so the ref silently resolved to nil. Segments now split
   into a base key plus trailing bracket tokens applied left-to-right
   (`[n]` descends, `[]` fans out and filters nils; `x[weird]` stays a
   literal key as before). Specs: `tests/http/zero_coverage_smoke_spec.lua`
   (+3). Also swaps the 4 deprecated `vim.tbl_islist` call sites
   (nested_access, jq_mapping) for `vim.islist` — nvim 0.12 warns on
   every request-vars resolution otherwise.
3. **vars: `@name =` (empty value) substituted as a literal `=`** — the
   primary pattern demanded one char after `=`, so the line fell through
   to the space-separator fallback which captured the `=` itself:
   `Bearer {{token}}` ran as `Bearer =`. All four copies of the scanner
   (vars ×2, format_file, copy) now capture the empty string; format_file
   renders the empty form without a trailing space. Spec: `vars_spec`
   (+2).
4. **curl tokenizer: three paste shapes mis-parsed** (each probed
   headless before the fix) — a hard-wrapped command (bare newline, no
   backslash) glued both lines into ONE url argument (`url="A\nB"`);
   `curl -d '' x` lost the empty quoted argument so `-d` ate the URL and
   the import failed with "No URL found"; the bare `curl` imported the
   literal URL `curl`. Newlines now separate argvs outside quotes (inside
   quotes they stay literal, shell rules); an argument that contained
   quotes always produces an argv; the bare `curl` is stripped before the
   URL scan. Specs: `curl_spec` (+4).
5. **feat(history): `D` clears all entries** — the browser only had
   per-entry `dd`; after a long session the only way out was deleting
   100 entries one by one. First `D` arms and announces the count, a
   second `D` within 3s wipes the ring, the id counter, and the persisted
   file (mq DELETE-confirm pattern, no modal dialogs); arming never
   outlives the window. Specs: `history_persistence_spec` (+1).
   In-repo `docs/user/keymaps.md` updated in the same change set.

## Recorded, not fixed (uncertain / deliberate)

- **VarResolver `or`-chain drops an explicit `false` env value** —
  `resolve()` falls through on `false`/`nil` (Lua `or` semantics), so
  `{"dev": {"flag": false}}` in env.json leaves `{{flag}}` literal while
  `true` substitutes. Env values are strings in every real env.json
  today; a fix means changing the resolution contract (distinguish
  "absent" from "false"), not a patch.
- **curl import: `https://token@host` (userinfo without `:`) is not
  redacted in command logs** — `redact_url_userinfo` masks only
  user:pass shapes, matching poste-mq's `redact_url` contract; a bare
  token in the authority is also a credential shape. Changing it is a
  cross-repo contract decision (do both repos in one change set).
- **Nested `client.test` swallows later outer asserts** — assertions.lua
  tracks one `current_test`; after an inner test returns, an outer
  `client.assert` failure raises but is recorded nowhere
  (`assertion_raised` suppresses the test-level record too). User-script
  misuse edge; a stack of open tests would fix it if it ever matters.
- **Sandboxed scripts have no instruction/allocation bound** — the
  whitelisted env stops `os`/`io`/`vim` access, but `while true do end`
  or `string.rep` still freeze/OOM nvim. Inherent to `load()` sandboxes;
  an instruction-count debug hook is the only real fix (feature-sized).
- **history.load: a decoded entry with a non-numeric `id` errors** on the
  `max_id` compare — corrupt-but-valid-JSON files only; decode failures
  are already handled.
- **Self-/mutually-referential `@var` defs churn until the 20-round
  substitution bound** and leave partial garbage (`@self = see
  {{self}}` → `see see … {{self}}`). Bounded by design; no fix short of
  cycle detection in the resolver.
- Carried unchanged from 09-20…09-23: copy_as_curl magic-var duplication,
  import_postman baked collection variables, json.get_key_paths array
  index enumeration, unsandboxed Lua imports, select.pick_snacks partial
  install, prompt_vars bounds, request names containing `.response.`,
  ai/actions.poll_completion stale-response race.
