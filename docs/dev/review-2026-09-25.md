## Fixed this round

1. **curl: semantic value letters inside a combined short-flag blob were
   silently dropped** — the blob walk (`-sS`, `-sSo out.txt`) treated
   every value letter as consume-and-drop. curl reads `-sd v` as
   `-s -d v`, but the importer produced a bodyless GET for
   `curl -sd '{"a":1}' url`, lost the header for `-sH 'Accept: …'`, and
   `-sXGET -d a=1` was promoted to POST by the later `-d`. H/X/d/F/u
   found inside a blob now dispatch through the same handlers as their
   dedicated branches (attached rest-of-blob value, else the next argv).
   Specs: `tests/http/curl_spec.lua` (+5).
2. **curl: the data-flags' POST promotion ignored an explicit `-X`** —
   `promote_post()` only compared `method == "GET"`, so even the
   non-blob `curl -X GET -d a=1 url` imported as POST. The promotion now
   respects `method_forced` (its declaration moved above `promote_post`
   so the upvalue exists — a forward reference would have read a global).
   Spec covered by the `-sXGET` case above.
3. **import_postman: `disabled` flags were imported as sendable lines** —
   Postman's `disabled: true` on query params, headers, and
   urlencoded/formdata body params means "not sent"; the importer copied
   them into the `.http` block, so a run would fire what the collection
   author switched off (an old `debug=1`, an `X-Off` header, a disabled
   `remember=true`). Disabled entries are now skipped.
   Also adds the importer's first real spec
   (`tests/http/import_postman_spec.lua`, +5: folder flattening, var
   resolution + unknown-var passthrough, body shapes) — beyond this it
   was covered only by the zero-coverage smoke probe; `_test_parse_item`
   follows the family test-hook convention.

## Recorded (uncertain / intentional)

- **`run #Name (@var=(1+2))` drops the override** — `parse_run_line`
  finds the `(...)` window with a greedy unbalanced-paren match, so
  nested parens slice the value and the `k=v` pair pattern rejects it
  (silently). A balanced-paren scan would fix it; rarity kept it out of
  this round.
- **`resolve_lua_imports` alias matching is prefix-ambiguous** — with
  aliases `m` and `m.data`, the line `@x = m.data.y` matches whichever
  alias `pairs()` visits first (both prefixes satisfy `m.`-prefixed
  matching). Dotted aliases are exotic; recorded.
- **`write_output` overwrites an existing `env.json`** on re-import into
  the same directory. Merging (or refusing) needs a UX decision.
- **Both transport argvs carry credentials** (`curl … https://u:p@host`,
  `poste mq-session --connection amqp://…`) — visible in `ps` on
  multi-user machines. The same item is on poste-mq's ledger; fixing it
  needs `-u`/netrc/`--config` plumbing per protocol.
- **`import_parser.example_to_string` renders nested objects as `[]`** —
  only reachable for object-valued OpenAPI parameters; cosmetic.
