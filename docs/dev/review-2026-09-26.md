# Review Notes — 2026-09-26

Scope: full test baseline (113 spec files green at start, 114 after) + a
fresh-eyes pass over the modules the 09-16…09-25 rounds touched least
(ai/auto_context, ai/system_prompt, constants, boundary_indicator,
context_detector, json_body, event, session, var_collector) plus
adversarial probes into the importers, response_parser, and shared util.

## Fixed this round

1. **curl importer: five real-world command shapes imported wrong or
   broke outright**
   - `--json '{"a":1}'` (curl ≥7.82): the value is a bare argument, so it
     won the first-bare-arg URL scan and the real URL vanished. Now
     imports as data-raw with BOTH implied `application/json` headers
     (explicit user Content-Type/Accept are kept, not clobbered).
   - `-I` / `--head` (and `-sI` in a blob): imported as a bodyless GET.
     Now HEAD, forced — the data flags' POST promotion may not clobber
     it, and an explicit -X still wins in either order.
   - `-u bob`: encoded `base64("bob")`, but curl sends `bob:` (colon
     appended for an empty password) — the imported Authorization header
     authenticated as a different credential string on the wire.
   - `--oauth2-bearer tok`: the token won the URL scan. Now an
     `Authorization: Bearer …` header.
   - `-A`/`--user-agent`, `-e`/`--referer`, `-b`/`--cookie` silently
     dropped their values (`-b`'s value could win the URL scan). Now
     mapped to User-Agent / Referer / Cookie headers; `-b` without `=`
     is a cookie-jar file — consumed, nothing mapped. These engine-set
     flags REPLACE, never repeat (last wins), matching the wire; `-H`
     keeps its append semantics.
   Specs: `tests/http/curl_spec.lua` (+11).
2. **importers: CR/LF in free-text fields split generated lines** —
   OpenAPI `operation.summary` is free text; a newline inside it split
   the `### name` line and the remainder imported as a bogus request
   line (the same family bug poste-mq's import.generate fixed for
   spaces on 09-25). `generate_http_block` / `generate_file_vars`
   flatten control characters at every single-line position via a
   shared `one_line` helper. Specs: `tests/http/import_postman_spec.lua`
   (+3). Lesson within a lesson: the first cut used `[%r%n]` — `%r` and
   `%n` are NOT Lua pattern escapes (`%n` is invalid, the class silently
   misbehaved); `%c` is the correct class for control bytes.
3. **boundary_indicator: stale paint + buffer-local scope** — the
   painted extmarks live in the buffer the cursor LAST moved in; the
   OFF path cleared only the CURRENT buffer, so toggling off elsewhere
   left the highlight visible on return. Fixed by clearing `_prev_buf`
   too. Then the deeper scope bug: the CursorMoved autocmd was
   `buffer = 0`-local, so toggling ON armed ONE buffer and the global
   command/notification silently lied — tracking dropped on the next
   buffer. The toggle is now genuinely global (CursorMoved/BufEnter on
   all buffers) with a `poste_http` filetype gate in the module (the
   cache's block scan keys on `###`, which markdown carries). The
   module's first spec (`tests/http/boundary_spec.lua`) covers both.

## Lessons (this round)

- **`%r` / `%n` are not Lua pattern escapes.** They are string escapes;
  in a pattern, an invalid `%`-letter class does not raise — it
  silently misbehaved (`[%r%n]` matched neither CR nor LF reliably).
  Use `%c` for control bytes or embed literal `\r\n` escapes in the
  pattern string. See LEARNINGS.md.
