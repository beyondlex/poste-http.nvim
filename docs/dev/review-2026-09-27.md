## Fixed this round

1. **curl importer: `-X` loses to `-I` in one order — wire-verified wrong**
   - `curl -X POST -I http://x` imported as HEAD; the real binary sends
     POST. Captured both orders against curl 8.7.1 with an `nc` listener:
     `-X POST -I` and `-I -X POST` both hit the wire as `POST` — the `-X`
     request token beats `--head` no matter which flag comes first.
   - The `-I` branch clobbered the method unconditionally; a trailing `-X`
     won (its branch also sets the method), which is exactly why the 09-26
     spec exercised only `-I -X POST` and baked the wrong expectation in
     for the other order. `-I` now forces HEAD only when no `-X` ran
     (`method_from_x` tracked separately from `method_forced`); `-I` alone
     or with data flags stays HEAD, `-XPOST`/`--request=` attached forms
     included. Specs: `tests/http/curl_spec.lua` (the order-agnostic test
     now asserts POST for both orders + attached forms).
2. **env winbar: two disagreeing "is this an http buffer" predicates** —
   `sync_winbar` also matched `.http`/`.rest` FILE NAMES (covers a file
   open before its filetype attached) while `set_env` refreshed only
   `filetype == poste_http` windows, so an env switch left such a window
   on a stale bar that the next BufEnter would then treat as its own and
   flip. Extracted one `is_http_buf` predicate used by both.
   (Refactor-level: `env_winbar_spec` green, no behavior change in the
   covered paths.)

## Recorded (uncertain / intentional)

- **Comment-line handling disagrees across layers** — `--`/`//`:
  `block_boundary.is_comment` and cache's request scanner treat a leading
  `--` as a comment (UI layer: indicators, block index), while the
  tree-sitter grammar's comment node is `#`-only, so describe.lua puts a
  `-- note` line in the header area into the BODY (`headers=0`,
  `-- note\nX-A: 1\n\nbody` all body). Docs on both sides say `--`/`//`
  are comment markers only INSIDE a JSON body — "everywhere else write
  `#`" — so the send-path behavior is the documented contract and the UI
  layer is the lenient one. Harmless today (the lenient layer only skips
  lines for display), but a third boundary layer must not grow.
- **curl importer: unquoted `--json {"a":1}`** (pathological shell input)
  arrives as body `{a:1}` — the tokenizer strips interior quotes that a
  real shell would have kept. Properly-quoted input (the 09-26 fix) is
  correct; a narrower fix would risk the `Name: value` pairing everywhere.
- **`assertion_error_line` maps chunk line N to marker_line + N** —
  correct because chunk line 1 is the line AFTER `> {%`; no direct spec
  (local fn), covered only via integration paths. Worth a spec if the
  chunkname ever changes (`[string "assertions"]` is matched literally).

## Lessons (this round)

- **Verify importer claims against the captured wire, and against BOTH
  argument orders** — the 09-26 note said "-X still wins in either
  order"; only one order had been checked. A two-line `nc -l` capture is
  cheaper than a wrong spec (see LEARNINGS 2026-09-19).
- **Probe the API, not the memory of it** — three probes this round were
  invalidated by wrong shapes (`collect_var_defs` is name-keyed;
  `parse_headers_file` takes headers-only dumps; `parse_curl` returns
  `(parsed, err)` not `(ok, …)`). Read the export list first.
