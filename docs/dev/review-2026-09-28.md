## Fixed this round

1. **image download: an HTTP error page was cached as the "image"** —
   `download_image_url` ran curl without `--fail`: a 404/500 response wrote
   its HTML body to the temp file and curl exited 0, so the error page was
   renamed into the cache as the image. The preview rendered garbage, the
   TTL kept serving it for the whole cache window, and the "stale fallback"
   path kept serving it forever after. `-f` now fails the call on HTTP
   errors, taking the same path as a transport failure (stale copy when
   present, notify + nil otherwise). Spec: `tests/http/image_cache_spec.lua`
   (argv carries `-f`; the stub-based specs never could reproduce this —
   they always simulate a successful body).

## Probes that passed (no change)

- **executors/graphql `split_body`**: array-shaped variables tail accepted
  as-is (nonsense for GraphQL, but the server rejects it — recorded, not
  guarded); broken `{`-shaped tail fails fast ("variables block is not
  valid JSON"); three-chunk bodies join the non-tail chunks with blank
  lines; `{{`-only body → whole-body query.
- **executors/websocket**: `split_messages(nil)`/blank bodies → no frames;
  `@ws-wait-ms -5`/`abc` → default 3000; mixed table/string frame shapes
  render. `chansend` right after a verified `jobstart > 0` cannot hit a
  dead channel (uv is single-threaded — no callback can have run yet), so
  the unguarded write is safe here, unlike poste-mq's post-async one.
- **json_body**: block comments spanning lines, `#`/`--` mid-line staying
  data (documented: line-start only), `https://x` inside strings surviving,
  unterminated block comment leaving the body verbatim (never guessed).
- **errors**: `{{a}} {{a}}` dedups; `find_var_line` finds the definition
  line inside a range.
- **block_operators**: extract with ranges entirely outside the line list

- **grpc_proto `body_context`**: `{{var}}` skipped atomically, string
  escapes, depth tracking on `}`/`]` — walked hand-traces on nested partials.
- **md5**: round constants, per-round k/s tables, and the padding formula

## Recorded (uncertain / intentional)

- **Non-image 200 responses are still cached as the image** — `-f` covers
  HTTP error statuses, but a 200 text/html page at a `.png` URL still lands
  in the cache (content-type is guessed from the URL, never sniffed from
  the bytes). A magic-byte check before `os.rename` would close it; left
  out to keep the fix one line.
- **ws_session survives a hidden response buffer** — closing the panel
  window with `:q` (buffer hidden, not wiped) keeps the interactive
  WebSocket streaming until `c`/BufWipeout. Deliberate design (frames stay
  copyable on reopen; busy is already released) — and importantly NOT the
  poste-mq tail leak: there the consumer destroyed messages with no UI;
  here nothing is lost and the close keys live on a reopenable panel.
- **GraphQL SDL unions with members on following lines** parse to an empty
  member list (the `= A | B` match is single-line). Completion-only
  degradation, valid SDL; would need a multi-line member scanner.
- **`run_request` wedges `_busy` if `resolve.resolve`'s callback never
  fires** (a prompt abandoned without answering). Every firing path clears
  it; the never-fires case is hypothetical until observed.

## Lessons (this round)

- **Stub-based specs inherit their blind spots** — the image_cache specs
  stub `vim.fn.system` to write a body and return `""`; every one of them
  models a successful transfer, so the real curl's exit-0-with-error-page
  behavior was invisible to the suite. When the code under test shells out,
  at least one spec should pin the argv against the REAL binary's contract
  (`-f` exists, `--` guards the URL), not just the happy path.
- **Cross-family bug hunting pays twice** — the poste-mq round found the
  window-lifecycle leak class; reading its sibling here (ws_session,
  image_cache) both confirmed the design difference and surfaced a
  different instance of "subprocess result trusted without checking the
  protocol-level outcome" (curl transport success ≠ HTTP success).
