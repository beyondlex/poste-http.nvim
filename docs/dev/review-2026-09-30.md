# Review Notes — 2026-09-30

Scope: full test baseline (114 spec files green at start) + cross-family
read (poste-mq's 09-30 round ran in parallel) + a read of the shared infra
(state, event, indicators, curl_exec, response_parser, history, jq_mapping,
nested_access) + adversarial probes against jq_mapping/nested_access,
collect_var_defs, util (redact/escape/line_splitter), the script sandbox,
and the pre-script logging path.

## Fixed this round

1. **The compact `@var=value` form split at the LAST `=` on the line** —
   the greedy `%S+` name backtracked to the last equals sign, so
   `@url=http://a?b=c` parsed as name `url=http://a?b`, value `c`. Query
   strings, base64 padding and JWT-shaped values were unreachable as
   `{{name}}` (the documented spaced form was unaffected, and the plugin's
   own injectors emit spaced lines). Both `collect_var_defs` and
   `collect_var_defs_with_lines` now split lazily at the FIRST `=`; an
   empty-name `@=value` line stays unregistered. Spec:
   `tests/http/vars_spec.lua`.
2. **Sandboxed scripts shared the process-wide stdlib tables** —
   `script_sandbox.build_sandbox_env` handed out THE `string`/`table`/
   `math`/`os` tables, so one shared `.http` script evaluating
   `string.format = junk` corrupted the whole nvim session until restart
   (the same shared-file threat model the curated `os` whitelist guards).
   Libraries are now `__index` proxies: reads fall through unchanged,
   writes raise and surface through the runner's pcall as a failed script.
   Spec: `tests/http/test_script_sandbox_spec.lua`.
3. **Pre-script `set()` calls logged the stored value verbatim** —
   `client.global.set('token', ...)` wrote the token to the log file in
   plaintext; script variables are exactly where tokens land and the log
   is a sync/screenshot leak surface (family rule: logs redact). Name and
   value LENGTH stay for debugging; the value never reaches the log.
   Spec: `tests/http/scripts_vars_spec.lua`.

## Probes that passed (no change)

- **jq_mapping / nested_access**: `get_nested_value(t, "")` → nil; the
  bare `.[]` wildcard mapping degrades to an empty field, never a
  `table: 0x…` leak; `parse_dynamic_mapping` for `{{Ref}}` / plain text;
  non-table values → `{}`.
- **collect_var_defs edges**: `>>>` with a missing `<<<` consumes to the
  range end (documented), `@var =` and `@var=` → "", `@=` unregistered,
  quoted values stripped, `@var value` space form intact.
- **util**: `redacted_cmd` sensitive-header / `-u` / URL-userinfo forms;
  `shell_escape` newline + CJK; `redact_url_query` bare tokens;
  `line_splitter` per its documented contract; `ensure_job_data` trailing
  empty trim; `json_to_table` vim.NIL nesting; `timestamp` ms shape.
- **response_parser**: hop-ordered Set-Cookie overwrite, final-block
  status, `HTTP/2 200` (no reason phrase) fallbacks, relative `Location`
  not promoted to the final URL.
- **curl parser**: attached `-XPOST`/`-H`/`-d`, blob walk (`-sSo`),
  `--json` implied headers, `-G` query rewrite, `--form-string` literal
  `@`, `;type=`/`;filename=` stripping.

## Recorded (uncertain / intentional)

- **curl importer: unlisted value-taking long flags** — `ignored_value_long`
  enumerates the common ones; an unlisted one (`--speed-limit 1024`,
  `--interface eth0`, …) leaves its value as a bare arg which can win the
  first-bare-arg URL scan when the command has no other URL. Enumerating
  all ~250 curl options is unwieldy and a URL-shaped heuristic risks
  regressing odd-but-legal targets; accepted limitation for now.
- **`load_env_vars_with_lines` (variable inspector) keeps escapes
  literally** — the hand parser for line mapping reads `"say \"hi\""` as
  `say \"hi\"` while the resolver's `vim.json.decode` path yields
  `say "hi"`. Only affects the inspector's display path; the substitution
  resolver is unaffected. Decide whether to unify before anyone hits it.
- **`session.lua` clears request-scoped state but `last_script_logs`
  accumulate within one run** — `set_assertion_results` appends its logs
  into `last_script_logs` and `begin()` resets the field per run, so the
  accumulation is per-request by design; noting it because the append
  shape looks like a leak at first read.

## Lessons (this round)

- **Greedy capture vs. first-separator data** — second bug of this shape
  in the family (poste-mq's redact_url last-@ was the deliberate
  counterpart): when a line format is "name<sep>value", name captures must
  be lazy, because the separator can also appear in the value. The spaced
  form hid this: `%s*` anchored the greedy run at the whitespace.
- **Sandbox hygiene is process hygiene** — a "sandbox" that shares the
  host's stdlib tables is not restricted at all for writes; the read-only
  proxy is now a family pattern (both repos, same commit round).
