# Review Notes — 2026-10-01

Scope: full test baseline (116 spec files green at start) + reads of the
modules prior rounds touched least (import.lua, import_openapi/import_swagger,
graphql_schema, grpc_proto, request_deps, file_include, env.lua,
boundary_indicator) + adversarial probes against graphql_schema's SDL parser
and body_context, grpc_proto's grpcurl-output parsers, vars' collect_var_defs
edges, and md5's padding boundaries.

## Fixed this round

1. **`run ./batch.http` progress notifications showed the wrong ordinal** —
   `execute_all_requests`'s `vim.schedule` callbacks read the shared `idx`
   upvalue at FIRE time; by then `execute_next` had already advanced it, so
   the first request's notification could show the second request's number
   and the last one printed `[n+1/n]`. The ordinal is now captured in a
   local before scheduling. Spec: `tests/http/import_spec.lua` (with a loop
   pump so the previous test's leftover schedules don't bleed into the
   capture table — a test-harness lesson in itself).
2. **`import`/`run` keyword guards required a literal space** — the guards
   matched `"^import "` / `"^run "` while the extractors matched `%s+`, so
   a tab-separated `import\t./path.http` line was silently not a directive.
   Guards aligned on `%s`. Spec: `tests/http/import_spec.lua`.
3. **OpenAPI/Swagger import emitted blocks in `pairs()` hash order** — the
   generated `.http` file is meant to be committed and reviewed, but its
   block order was a function of Lua's hash iteration: the same spec could
   import in a different order per run/session. Paths are now sorted before
   iterating, and a malformed spec with a non-table path item (number,
   string, JSON null) is skipped instead of crashing mid-import. First
   end-to-end specs for both importers:
   `tests/http/import_openapi_swagger_spec.lua`.
4. **`:PosteHttpEnv <typo>` switched silently** (UX) — an unknown env name
   updated `state.current_env`, every `{{var}}` then resolved to nothing,
   and the request went out with literal placeholders. `set_env` now
   validates against the env.json walk-up when one is discoverable
   (unknown name → warn listing the valid names, no switch) and stays
   permissive when the file is absent or unparsable. `pick_env` reuses the
   same discovery helper and now names the broken file when it cannot
   parse it. Spec: `tests/http/env_switch_spec.lua`.
5. **`request_deps.split_request_ref` doc comment described a grammar the
   code doesn't implement** — the comment claimed "the last marker splits"
   while the code (and `ai/blocks.lua` `dep_names`, which mirrors it) takes
   the first `.response.`/`.request.`, whichever occurs later. Comment
   corrected; the limitation is now named: a block name containing the
   same marker twice cannot be referenced.

## Probes that passed (no change)

- **graphql_schema**: `parse_sdl` with an unterminated string containing
  definition keywords, `extend extend type`, leading-pipe unions,
  unterminated enums, keyword-named fields (`type:`/`input:`/`enum:` inside
  a body); `body_context` with empty input, unbalanced braces/parens,
  `{{` string tokens, a dangling `$var:` — all degrade, none raise.
- **grpc_proto**: `parse_list_output`/`parse_describe_output`/
  `parse_type_describe` on garbage input return empty/unknown kinds.
- **collect_var_defs edges**: `@a=b=c` splits at the FIRST `=` (09-30 fix
  holding); `@var name = x` → spaced form value "name = x"; `@=` rejected;
  quoted values stripped; `>>>` consumes to `<<<` or range end.
- **md5**: RFC 1321 vectors + 56/57-byte padding boundaries already
  covered by `tests/http/md5_spec.lua`.
- **file_include**: `< {%` exclusion (incl. `<  {%` with two spaces),
  directory-read error surfaced (09-2x fix holding).

## Recorded (uncertain / intentional)

- **`{{alias.}}` (Lua import, empty keypath) resolves to the WHOLE exports
  table as JSON** — `resolve_path_for_export(exports, "")` returns the
  table itself. Mirrors poste-mq's recorded `{{Name.}}` whole-metadata
  behavior; defensible, unify across the family if anyone hits it.
- **grpc_proto `build_list_args`/`build_describe_args`/`index_key` crash on
  a nil `info`** — unreachable today: every public entry point
  (`prewarm`/`get_method_items`/`get_body_items`/`ensure_message` callers)
  guards nil first. Add guards only if a new caller appears.
- **Import/run directives are recognized anywhere in the file** — a body
  line starting with `run ` reads as a directive. Fixing it needs
  block-aware scanning in `collect_directives`; low real-world risk (bodies
  starting a line with `run ` are rare), accepted for now.
- **Swagger `build_url` does not normalize a leading `/`** on the path
  (OpenAPI's does). Swagger 2.0 paths always start with `/` per spec; the
  importer already rejects non-table path items, so only a spec-violating
  path could hit it.

## Lessons (this round)

- **Shared upvalues + deferred callbacks = read-at-fire-time bugs** — same
  shape as the classic loop-closure bug, one level up: `vim.schedule` /
  job callbacks must capture the values they print, never the mutable
  index. The mq family's `run_sequence` already schedules `next_block`
  itself (not the index) — keep that shape.
- **Generated files must be pure functions of their input** — anything a
  user commits (imported .http files) may not depend on `pairs()` order.
  Sort before iterating, every time, even when the source "usually" has
  stable order.
