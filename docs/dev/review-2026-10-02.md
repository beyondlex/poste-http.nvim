# Review Notes — 2026-10-02

Scope: full test baseline (118 spec files green at start) + first-deep reads
of the modules prior rounds touched least (`ai/*` end to end, `executors/*`,
`ws_session`, `format/multipart`, `format/messages`, `format/body`,
`format/util`, `format/verbose`, `nav/util`, `jq_mapping`, `errors`,
`install`, `health`, `buffer_setup`, `select`, `event`, `state`) + two
adversarial probe batteries against the pure layers (probe scripts covered
multipart parsing, json_pretty, url_decode, graphql split_body, jq_mapping,
websocket/grpc helper math, errors scanning, curl-import tokenizing,
response_parser, nested_access, describe, block_operators, history add_entry).

## Fixed this round

1. **`format/util.url_decode` returned two values** — a bare
   `return s:gsub(...)` ships the substitution count after the string.
   Every current caller assigns to one variable so nothing broke, but any
   future varargs/table-constructor caller silently gets the count too.
   Now parenthesized to the documented one-value contract, with a spec
   pinning `select("#", url_decode(...)) == 1`.
2. **`format/util.json_pretty` crashed on mixed number/string keys**
   (`table.sort` raised "attempt to compare number with string"). JSON
   decode can't produce that, but Lua-built tables (sparse arrays from
   filters) can reach it. Type-aware comparator: numbers sort before
   strings, same-type pairs compare normally. Specs for the mixed-key and
   sparse-array shapes.
3. **`executors/graphql.split_body` accepted a JSON array as the variables
   block** — Lua decodes `[1,2]` to a table, so it passed the type check
   and shipped as `"variables": [1,2]`, failing only server-side with
   "variables must be an object". Now rejected up front with
   "must be a JSON object" (the module's fail-fast rule). Spec added.
4. **`event.once` handlers fired again after raising** — the wrapper called
   `handler(data)` bare; the error propagated to `emit`'s pcall and the
   self-removal never ran, so the next emit invoked the "once" handler a
   second time. The wrapper now pcalls the handler, removes itself, then
   re-raises via `error(err, 0)` so emit's notify path is preserved. Spec
   asserts exactly-one-fire + empty handler table + one notify.
5. **`install.force_build` reported ERROR on a healthy install** —
   everything-up-to-date collapsed into the same "No parsers were
   compiled" failure as real build errors. `compile_one` now returns a
   tri-state (built / up_to_date / failed) and `force_build` says "All
   parsers are up to date." (INFO) when nothing needed building. Also
   fixed the circular no-compiler advice ("run :PosteHttpBuildParsers"
   while inside that command). Spec injects fresh mtimes and asserts
   up-to-date INFO without the failure notify.
6. **`ws_session` leaked its buffer-local `s`/`c` keymaps after finalize** —
   the response buffer is reused by later non-WS runs, where a stale `s`
   popped "No live WebSocket session" forever. finalize now unmaps the
   session-only keys (resolved through the same config lookup, so a
   user-disabled action was never registered and is not deleted). Spec
   mocks `vim.keymap.del` and asserts both keys go.
7. **`errors.find_unresolved_vars` crashed on a non-string/non-table
   argument** (`ipairs(123)`); hardened to the same "garbage in → {}" as
   the existing nil case. Probe-pinned.

  bare closing delimiter, regex-magic boundary (`a+b(c)`) with literal
  find — all degrade correctly.

  json content type.

  metadata.method, multipart garbage falls back to a named "parse failed"
  card, `format_response_size` zero paths.
- **jq_mapping**: empty/comma-only option strings, `desc|` rename, plain
  `{{ref}}` without mapping, nil/scalar values, missing keypath → empty.
- **curl import (parse_curl)**: `-d ''` keeps the URL (09-22 lesson
  holding), method default GET, backslash continuations, `-H 'X-Empty;'`,
  `-d @file`, `--data-urlencode`, garbage inputs degrade or error.
- **response_parser**: non-response text, empty, unknown status 999,
  header line without a colon, chunked-looking body — all parse or
  degrade; nothing raises.

  index-into-array-by-key, scalar doc — nil results, no raises.
- **Lua-pattern false alarm checked**: `line:find("?", 3)` in verbose.lua
  looked like a malformed bare `?` pattern; LuaJIT and Lua 5.5 both treat
  a leading bare `?` as literal. No change needed.

## Recorded (uncertain / intentional)

- **`install.compile_one` interpolates paths into a shell string** without
  fnameescape — a plugin checkout under a path with spaces breaks the
  compile. Not reachable through the lazy.nvim default layout; fix when
  a user actually hits it.
- **`nav/util.goto_env_var` brace counting** accepts at most one brace per
  line and counts braces inside JSON strings — a minified env.json makes
  the section scan run to EOF (navigation-only, worst case jumps to a
  same-named key of another env).
- **`nested_access` has no quoted-keypath syntax** — `['weird.key']` is
  parsed as a literal segment, so JSON keys containing dots are
  unreachable from `{{…}}` refs. Same documented-limitation family as
  `a..b` degrading to literal segments.
- **`env.discover_env_names` on a JSON array env.json** yields number
  "names"; `pick_env` would offer them and `set_env` would accept the
  number back. Only reachable with an invalid env.json; validation stays
  permissive by design.
- **`ai/actions.poll_completion` timeout message** ("did not parse as a
  request") is also shown when a `run` directive failed without setting
  errors — cosmetic mislabel on a rare path.
- **`format/multipart.parse_multipart_parts` returns nil for a CRLF body
  whose closing delimiter is missing** — curl always terminates the
  multipart body it sends, so unreachable through the pipeline.

## Lessons (this round)

- **`return f:gsub(...)` ships two values** — the substitution count rides
  along with any gsub result returned bare. When a helper's contract is
  "returns a string", parenthesize the tail call; the bug is invisible
  until a caller consumes varargs.
- **A build command must distinguish built / up-to-date / failed.**
  Collapsing "nothing to do" into failure turned `:PosteHttpBuildParsers`
  on a healthy install into an ERROR with a bad "Check :PosteInfo" hint.
  The same tri-state rule the family applies to network responses
  (empty-is-legal vs no-answer) applies to build tooling.
- **Buffer-local keys owned by a session need teardown at session death**,
  not at buffer death — the response buffer outlives the session that
  registered the keys (09-28's WinClosed lesson, one layer up: the owner
  there was the window, here the ephemeral session).
