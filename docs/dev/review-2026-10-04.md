## Fixed this round

1. **`apply_jq_mapping` put a table address in option labels** — a
   mapping path that lands on an object/array (`desc: .items` while
   iterating the parent) was `tostring()`ed into `table: 0x…` as the
   picker's option text. Tables now JSON-encode (encode failure degrades
   to a placeholder), matching the vars-layer table rule. The two
   iteration modes also computed the identical item list twice — hoisted.
   Spec: `request_vars_structured_spec` (object path encodes).

2. **`:PosteHttpBuildParsers` did not exist** — health.lua (3 warns) and
   install.lua direct users at it when a parser is missing or stale, but
   the command was never registered; the guidance named a command that
   could not run. It now dispatches to `install.force_build()` (whose
   "All parsers are up to date." path was already maintained for exactly
   this surface). Spec: `commands_spec` (dispatch).

3. **Command doc lists drifted from the registry** — `:h poste-http` and
   README listed `:PosteHttpInfo` and `:PosteHttpTSStatus`, which exist
   nowhere in the code, and omitted `:PosteHttpHistoryClear`. The tables
   now match `commands.lua` + `boundary_indicator.lua` exactly.

4. **A cursor with no request died silently** — `<CR>` outside a `###`
   block (or in a block without a request line) cleared the indicators
   and returned with no word; the key looked dead. It now notifies
   "No request at cursor …" and still releases the busy flag (poste-mq's
   run_cursor carries the same message). Spec: `run_spec`.

## Probes that passed (no change)

- **graphql split_body/build_request_body**: 10 shapes — no tail,
  variables object, mid-body extra chunk (tail-only rule), array tail
  (rejected as an error, not sent), broken JSON tail (fail fast),
  whitespace-only tail, empty body, CRLF blank lines, `{}` tail,
  trailing text after the JSON tail. All land on the documented rule.
- **websocket**: wait-ms 0 / negative / junk / `1e3` fall back to the
  default sensibly; CRLF bodies split clean; failure carries status 1006
  with the first stderr line as status_text.
- **grpc**: full target, bare-host reflection `list`, trailing-slash and
  dot-method completeness checks, nil header values, unknown code names
  (protocol error, not a fabricated status).
- **response_parser**: a 3-hop -D dump (200 → 301 → 200) picks the final
  block and merges Set-Cookie across hops with overwrite semantics;
  headerless output falls back to "No Response"; `HTTP/2 204` with no
  reason phrase renders from the reason table; `X-Empty:` survives as an
  empty value and junk lines are dropped.
- **run pipeline nil-tolerance**: `extract_script_blocks` /
  `inject_global_vars` / `scan_script_set_calls` all handle a nil
  block_start (defensive checks were already in place).

## Recorded (uncertain / intentional)

- **Blockless `.http` files build an implicit block from the request
  line** (cache's scan starts at the first `METHOD url` line) — so
  `run_request` on a plain-text buffer with `METHOD /x` will run it.
  Discovered while testing fix 4; long-standing documented behavior of
  the cache, unchanged.
- **`vars.value_to_string` falls back to `tostring(table)`** when
  `vim.json.encode` fails — only reachable with a cyclic variable value
  (env.json/JSON decode cannot produce one today); the garbage string
  would surface instead of a crash. Left as-is; recorded.
- **`grpc.parse_target` on a leading-slash target** (`GRPC /pkg.Svc/M`)
  reads the whole thing as a bare host and issues a reflection `list`
  against it — grpcurl then errors confusingly. A user typo; a validator
  would need the host/method grammar spelled out for marginal benefit.
- **`websocket.resolve_wait_ms` has no upper bound** — `@ws-wait-ms
  999999999999999999` arms a timer that effectively never fires and
  holds the panel open. Self-inflicted; the curl/grpc paths cap at
  `--max-time`, websocat has no equivalent flag wired.
- **`curl_exec` sends no `--data-binary` for an empty body** — an
  explicit empty-body POST (Content-Length: 0 on the wire) has no
  representable form; nobody has asked for it.

## Lessons (this round)

- **User guidance is part of the command's contract** — health.lua told
  users to run a command that was never registered; the message path and
  the registration must ship in the same change set (the family's
  "grammar ↔ data sync" rule, one level up: message ↔ command).
- **Doc tables drift silently** — two phantom commands survived in
  `:h poste-http` and README for months because nothing greps them. The
  fix was mechanical; a drift test (commands_spec already enumerates the
  registry) is the cheap guard going forward.
- **Walk results are not display strings** — `tostring(x)` on a walk
  result is only safe when the path grammar guarantees a scalar; when it
  doesn't, encode (or type-check) at the formatting boundary. Same
  lesson as poste-mq's env-table fix this round.
