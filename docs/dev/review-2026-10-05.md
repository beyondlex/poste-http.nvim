# Review Notes — 2026-10-05

Scope: full test baseline (118 spec files green at start) + adversarial
probes over the never-probed nav family (15 reference shapes through
nav.util, nav.text, nav.ts) + first reads of the never-reviewed
modules (nav.ts/nav.text/nav.util in full, buffer.lua, help.lua,
state.lua, event.lua, http/nav.lua aggregator) + a duplication audit
across the nav resolution chains.

## Fixed this round

1. **`K` on a table-valued env variable crashed the value preview** —
   `load_env_vars` stores env.json values RAW, so `{"dev": {"cfg":
   {"a": 1}}}` made `show_var_value` call `resolved:find` on a Lua
   table ("attempt to call a nil value"), and a JSON null resolved to
   the truthy vim.NIL userdata and crashed the same line (poste-mq
   fixed the substitution twin of this on 10-04; the inspector was the
   http-side sibling). Display now goes through `vars.value_to_string`
   (exported; same stringifier `substitute()` uses): tables render as
   JSON, nulls as (unresolved). Spec: `vars_spec` (stringifier contract
   + resolver raw-shape proof).

2. **Eight response keys rendered with an empty help description** —
   `view_request`, `view_errors`, `next_response`, `prev_response`,
   `json_filter`, `json_restore`, `json_toggle_raw`, `json_outline`
   were configured keymaps without DESCRIPTIONS entries; the `g?`
   float showed a bare key and blank text. Descriptions added, and a
   drift-guard spec now fails when any configured action lacks one.
   Spec: `help_spec` (per-section enumeration).

3. **`view_messages` / `ws_send` / `ws_close` were live keys missing
   from the config defaults** — registered via `register_all` defaults
   and documented in docs/user/keymaps.md as configurable, but absent
   from `state.config.keymaps`, so the Msgs tab showed no `[M]` hint
   and `g?` omitted all three. Added to the defaults; runtime keys
   unchanged. Spec: the help drift-guard covers them.

## Refactor (behavior-preserving, test-covered)

4. **The nav import-keypath dance existed six times** — "find aliased
   import → jump to its alias | open the file at the first key" was
   copy-pasted across nav.ts's identifier / variable / var_value /
   import_var_ref branches and nav.text's @var branch (two of them at
   different indents, one behind a replace-all-proof). They now share
   `nav_util.goto_import_keypath(buf, alias, keypath, { alias_half })`;
   the twin 80-line identifier/variable resolution chains also
   collapsed into one `goto_var_definition()` (nav.ts: 579 → 396
   lines). Per-shape semantics preserved (fall-through vs "Import not
   found for alias"). nav_spec gains the first coverage for the
   identifier/variable chain (in-block @token, file-level @base_url,
   dotted `{{Login.token}}` → ### header): 14 → 17 tests.

## Recorded (uncertain / intentional)

- **`nav.util.goto_env_var` counts braces with `l:match("{")`** — one
  brace per line regardless of count; a one-line nested section could
  end the section scan early. Pretty-printed env.json (the norm) is
  unaffected; a gsub-count rewrite is cheap if it ever bites.
- **`collect_references`' plain-word scan adds comment lines** — the
  second pass (Lua identifiers) has no `^%s*[#%-]` exclusion, so `--
  token` mentions become references. Possibly intended (script blocks
  are the target surface); left as-is.
- **`show_references` re-parses its own formatted "L%d:%d:" strings**
  to jump — a string as the data record; works, just lossy if a line
  ever contains the prefix.

## Lessons (this round)

- **The resolver's env layer returns RAW decoded JSON** — every other
  layer stringifies (value_to_http_string, value_to_string), so the
  display boundary that assumed strings was the odd one out. Family
  rule restated: decode boundaries may hand out tables/vim.NIL; any
  `.method` call on a resolved value must stringify first.
- **Docs-vs-config drift inverts** — this round the user docs listed
  keys the config defaults lacked (last round it was commands the docs
  listed that the code lacked). Both directions are the same defect:
  two tables claiming to describe one surface. The drift-guard spec is
  the cheap fix in either direction.
- **A replace-all refactor proves the copies** — the second nav alias
  copy survived the first cleanup purely by different indentation.
  When duplicated blocks are found, unify them in the same round; the
  copies only ever drift further apart.
