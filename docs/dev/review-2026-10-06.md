# Review Notes — 2026-10-06

Scope: full test baseline (118 spec files green at start) + fresh reads
of util/state/event/data/vars/curl_exec/response_parser/run/history/
cache/json/script_sandbox + a cross-project adversarial round against
the hostile-data surfaces (env.json shapes, var-name spellings,
OpenAPI/Postman spec shapes) written as throwaway nvim scripts before
any fix.

## Fixed this round

1. **A non-table env.json section crashed the whole resolve chain** —
   `{"dev": 42}` (a typo'd environment value) came back from
   `load_env_vars` as the raw number; the next `self.env[name]` inside
   `resolve()` raised "attempt to index a number value" mid-pipeline,
   wedging `state._busy = true` until restart. `cache.collect_env_vars`
   (completion) already guarded this exact shape — the run path just
   never got the same guard. Spec: `vars_spec` (hostile env shapes).

2. **A `false` env value fell through every resolution layer** — the
   `or`-chain in `VarResolver:resolve` reads `false` as "missing", so
   `"flag": false` resolved via the magic-var fallback to nil and
   `{{flag}}` stayed unresolved instead of substituting "false".
   Replaced with explicit `v ~= nil` layer checks (poste-mq's
   `resolve_expr` already checked `~= nil`). Spec: `vars_spec`.

3. **`{{ host }}` (spaced name) silently did not resolve** — poste-mq
   trims inside `resolve_expr`; the http-side capture went to the
   lookup verbatim. Trim on resolve, keep the original (spaced) text
   on the unresolved re-emission so the error report echoes what is
   written. Spec: `vars_spec`.

4. **copy.lua's private env/@var copies had drifted from vars.lua** —
   three defects in one module, all on the multipart `-F` path: its own
   `load_env_vars` had bug 1 (crash via `pairs()` over a number), its
   `collect_var_defs` still used the greedy `%S+` name that vars.lua
   fixed on 09-17 (`@token=eyJ9.abc==` captured name "token=eyJ9.abc"),
   and a table-valued env var went into `gsub` as the replacement value
   ("invalid replacement value (a table)"). All three now delegate to
   the vars module's shared implementations; `substitute_vars` trims
   and stringifies through `vars.value_to_string`. Specs: `copy_spec`
   (hostile collect_vars shapes).

5. **Hostile import-spec shapes crashed the importer** — a `$ref`
   resolving to a scalar (`#/info/version` → 42) crashed
   `schema_to_example` on `.example`; a scalar entry in a parameters
   array crashed `resolve_schema` on `schema["$ref"]`; junk-typed
   `properties`/`enum` crashed `pairs`/`table.concat`. Scalars now pass
   through (a scalar is its own example) and wrong-typed containers
   degrade to empty. Spec: `import_spec` (hostile shapes describe).

## Recorded (uncertain / intentional)

- **Three env.json loaders still exist** — `vars.load_env_vars`,
  `vars.load_env_vars_with_lines`, and `cache.collect_env_vars` walk
  the same tree with three parsers (json-decode / line-scan /
  readfile+decode). The line-scan variant exists for per-key line
  numbers (K display), the cache one for completion caching; both now
  agree on the non-table guard. A single loader with an optional line
  map would remove the trio, but the line-scan semantics (brace
  counting outside strings) are subtle and currently tested — left as
  a recorded smell, not a refactor.
- **`resolve()` treats an explicit JSON null env value as ""** —
  `value_to_string(vim.NIL)` returns the empty string, so
  `{"x": null}` substitutes "" while poste-mq leaves `{{x}}`
  unresolved (its `is_null` check). Both defensible; the http-side
  contract ("" since the stringifier landed) is now pinned by spec, so
  a change either way is visible.
- **`response.ok` is false for 3xx** — with `-L` the final response is
  what ships, so a 304/308 terminal status reads as failure. Matches
  "ok = status < 400" as written; flagging in case a redirect-not-
  followed distinction is ever wanted in the UI.
- **`shell_escape` allows a leading `-` through unquoted** — safe
  today because the only free-position argument (the URL) sits behind
  `--` in curl_exec, and every other `-`-bearing string is an option's
  optarg. The invariant is one refactor away from being load-bearing;
  noted so nobody reorders the argv casually.

## Lessons (this round)

- **The same hostile-data class lived in five modules across both
  repos** — non-table sections, scalar array elements, wrong-typed
  containers: every one was a "decode boundary hands out whatever JSON
  said" site. The family rule now reads: any `pairs`/`ipairs`/index
  over decoded data guards the element type first; the guard goes in
  the pure layer (format/model/import), not just the transport.
- **A swallowed pcall converts a crash into a hang** — topology's
  render pcall turned the scalar-items crash into "(fetching
  topology…)" forever. A pcall that catches must surface (log +
  notify); bare `pcall(f)` is only acceptable when the caller owns the
  retry.
- **Drifted private copies were the second bug factory** — copy.lua's
  env loader and var collector each kept a bug that the shared module
  had already fixed. Delete the copy in the same round the drift is
  found; delegation is smaller than the diff of re-fixing it.
