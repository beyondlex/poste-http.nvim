Scope: full test baseline + fresh reads of copy/nested_access/jq_mapping/
form_data/file_include/response/errors/semantics/event_bus/block_boundary/

## Fixed this round

1. **The suite baseline itself was red** — `http_image_preview_spec`'s
   "renders a fresh cached copy without downloading" wrote its fake cache
   file into the real stdpath cache, whose `img/` subdirectory only ever
   exists after a real download (`new_temp_download_path` mkdirs it). On a
   clean XDG cache `io.open` failed with ENOENT and `./tests/run.sh`
   exited 1 while every other spec passed. The spec now mkdirs the parent,
   mirroring the download-URL-caching block. Finding it needed a
   per-spec child run with plenary's exact directory-run args
   (`--noplugin -u tests/minimal_init.lua`): `PlenaryBustedFile` skips
   minimal_init and reports load failures, not test failures.
   Spec: `http_image_preview_spec`.

2. **A quoted multipart boundary silently emptied the copied curl
   command** — `copy_as_curl` extracted the boundary with
   `boundary=([^;]+)`, which keeps the quotes of `boundary="BOUND"`. No
   body line ever matched `--"BOUND"`, so `build_multipart_flags` produced
   zero `-F` flags and the copied command lost the entire body while the
   real run sent fine. The extraction now reuses
   `format/multipart.extract_boundary` (quoted-form-first — the same rule
   the response viewer uses; DRY with the one correct copy).
   Spec: `copy_spec`.

3. **jq_mapping indexed non-string input** — `parse_structured_options`
   called `:gmatch` on whatever it got and `apply_jq_mapping` called
   `:gsub`/`:find` on mapping path values. Unreachable from today's call
   sites (prompt_vars matches both out of buffer lines), fixed for the
   module's own convention — same consistency sweep as ai/blocks +
   ai/mentions on 10-07. Specs: `request_vars_structured_spec`.

## Recorded (uncertain / intentional)

- **`block_boundary.compute_block_range` assumes a real lines array** —
  `#lines` on nil raises; both callers (describe, cache) pass buffer
  lines, and the module documents the parameter as `string[]`. Left
  unguarded — a type guard here would paper over a caller bug rather
  than surface it.
- **sandbox_os.getenv stays available** — documented as intentional in
  script_sandbox.lua (time/clock/env reads allowed; no shell/fs/exec).
  Re-flagged during this round's sandbox read and re-confirmed as a
  design decision, not drift.

## Lesson this round

A probe note that asserts platform behavior must be verified in the
platform. The sibling repo's 10-07 notes recorded "nvim_buf_set_lines
splits embedded newlines for you" — the API actually rejects them, and
that wrong conclusion postponed a real crash fix by a round. Both repos'
10-08 notes carry the correction.
