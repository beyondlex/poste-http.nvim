# Review Notes — 2026-10-09

Scope: full test baseline (118 spec files green at start) + first-deep
reads of the modules prior rounds touched least (`textobj`, `folding`,
`ts_query`, `symbols`, `view`, `script_block`, `script_snippet`,
`scripts` inject/scan layer, `completion`, `item_builder`) + adversarial
probes (throwaway spec, deleted before commit) against: multi-line
values through the inject layer, the textobj motion feed, foldexpr on
single-line bodies, and paste_curl with quoted multi-line argv values.
Cross-family angle: re-ran poste-mq's parse/dialect through the shapes
this round produced in poste-http (see poste-mq's notes).

## Fixed this round

1. **A multi-line script-set value tore the request open** —
   `inject_pre_script_vars` / `inject_global_vars` string.format-ed any
   value into ONE `@name = value` line. A value with an embedded newline
   (`client.global.set` of a multi-line body, a `>>>/<<<` heredoc file
   var carried through a script) landed its second line in the content
   as a bare request line, and both callers bumped `block_end`/`line`
   by `pairs(variables)` — under-counting every extra physical line, so
   assertion blocks near the block end silently fell outside their
   extraction range. Multi-line values now serialize as the grammar's
   own `>>>/<<<` heredoc form (collect_var_defs round-trips them
   exactly), a value of exactly `>>>` is quote-wrapped so it cannot
   re-parse as an opener, and both inject functions return the PHYSICAL
   line count (the heredoc value line carries embedded newlines) which
   run.lua / import.lua now consume. Spec: `run_spec`.

2. **paste_curl failed on a quoted multi-line -H value** — parse_curl
   keeps newlines inside a quoted argv value (legal in the curl command,
   pasted from a doc), curl_to_http embedded them verbatim in one output
   line, and nvim_buf_set_lines raises "replacement string item contains
   newlines": the paste threw out of the keymap and inserted nothing.
   Header values and the URL now fold CR/LF runs to single spaces (a
   header cannot carry a bare CRLF on the wire anyway). Spec: `curl_spec`.

3. **RUN outline rows lost their method to bare uppercase body lines** —
   collect_requests scanned past the RUN target line for a request-line
   match; a body line that is a bare uppercase token (`TRUE`, `NULL`, …)
   hit the `%u+$` branch, overwrote the method column entry and dropped
   the run target. Both branches break once the request line is found.
   Spec: `symbols_spec`.

4. **A `###` line always starts the next block, even after a body with
   no blank line** (grammar root cause) — json_body/graphql_body
   continuations were blanket "any non-blank line", so two adjacent POST
   blocks parsed as ONE json_body swallowing the second block's
   separator, request line and body — highlight and fold ranges bled
   across the boundary. Continuation lines now exclude `###`-shaped
   lines; single-`#` lines stay body text (legal GraphQL comments, and
   JSON has no #-lexeme). Corpus: adjacent bodies without a blank line,
   single-line body followed directly by the next separator. The
   execution path (regex describe) was never affected — this is the
   presentation tree only.

5. **foldexpr emitted the invalid fold start `>0` for single-line
   bodies** — `POST` with an inline `{"a":1}` body returned `>0`
   (illegal fold level) and nested the line below into a phantom fold.
   A single-line foldable node now returns `=`. Spec: `folding_spec`
   (parser-gated).

6. **Spaced `{{ base }}` refs in var values resolve now** — the
   pre-script layer's private resolver looked the captured `{{...}}`
   name up verbatim while `VarResolver:substitute` trims; `@url = {{
   base }}/u` stayed raw in script variables but substituted in the
   request. Trim before lookup, and skip non-string values instead of
   crashing on `v:gsub` (defensive — today's collectors are
   line-derived strings). Spec: `scripts_vars_spec`.

## Added this round

7. **Text objects wired at last** (`aR` / `iH` / `iB` / `iS`, visual
   mode) — textobj.lua shipped with the tree-sitter migration and
   nothing ever mapped it; reading it closely showed its selects could
   never have worked anyway: they walked up from a request-line node to
   a `request_block` ancestor, but the grammar's request_block node is
   ONLY the `### Name` line, never an ancestor of anything. The module
   now computes block ranges itself (separator row through the last
   non-blank line before the next separator), selects headers from the
   first/last `(header)` captures within the range, and maps everything
   through the standard config keymap system (x-mode only, `<Plug>`
   aliases ride along). Deliberately NO operator-pending mapping: an
   operator consumes exactly one motion, and these ranges are a
   two-motion walk (end, `o` swap, start). The help window, the user
   keymaps doc (whose full-defaults block had drifted — `run_hsplit`
   and `show_variable_inspector` were missing) and the file index
   updated. Spec: `textobj_spec`.

## Probe batteries that passed (no change)

- **ts_query** — the capture-id shim (`capture_names[id] or
  query.captures[id] or [id + 1]`) holds across node/table match
  shapes; `node_text` on multi-line and 0-length ranges.
- **textobj motion math** — feeding `sc|` instead of `sc+1|` is one
  byte short on non-zero columns, but every selectable node type starts
  at column 0, so the old copies never misfired; fixed for consistency
  in the rewrite.
- **folding cache** — the per-buffer tick keying and BufWipeout eviction
  hold (the spec already covers the equal-tick collision).

## Recorded (uncertain / intentional)

- **`serialize_var_line` cannot round-trip a value whose OWN line is
  `<<<`** — the heredoc grammar has no escape for a terminator line
  inside the value; such a value (from a script setting
  `"a\n<<<\nb"`) re-parses truncated. Values that hostile have to come
  from a script deliberately; recorded, not fixed (no syntax exists to
  invent without a grammar change).
- **inject order is pairs() order** — several variables inject in
  hash order, so the injected lines' relative order varies run to run.
  Only matters for byte-stability of the modified content, never for
  semantics (each var is independent lines); recorded.
- **o-mode text objects** — see 7; re-visit only if a future nvim
  exposes operator-span marks to Lua.

## Lessons (this round)

- **"Dead code" and "never-worked code" travel together** — textobj.lua
  had no mapping since migration AND its node walk targeted a node type
  that can never be the ancestor it needed. When a module has zero call
  sites, the first deep read should try to trace whether it COULD have
  worked if wired, not just whether it is wired.
- **Text round-trips need a serialization step** — same lesson family
  as 10-08's copy.lua: any time a value leaves the value world and
  becomes buffer text, the grammar's own quoting/escaping form is the
  only lossless spelling, and the physical line count it produces is
  the only number the line bookkeeping may consume.
